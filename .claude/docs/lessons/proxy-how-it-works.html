1. Big Picture — What the Proxy Does

Garnet sits between Open WebUI (the chat interface) and any LLM (OpenAI, Anthropic, Ollama, Groq, Gemini…). Its job: replace real names / emails / IBANs with random tokens before they reach the LLM, then swap them back in the response.

User writes →
"Max Mustermann at
Enclaive GmbH sent
IBAN DE89 3704 0044…"
→
proxy
→
LLM sees →
"PERSON_cc75010d at
ORGANIZATION_bd3a68a5
sent IBAN_CODE_f4e21a…"

The LLM never sees real PII. The user gets back a perfectly readable answer — the proxy restores everything on the way out.

2. Request Flow — Step by Step

1
Receive
proxy() catches every POST to /v1/chat/completions
2
Scan history
Each message in the chat history is checked for PII
3
Pseudonymize
PII → tokens via GLiNER + Presidio + regex
4
Forward
Cleaned request → LLM provider over HTTPS
5
Restore
Tokens → real values in the response before user sees it

Where this happens in code

# main.py — the catch-all route
@app.api_route("/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def proxy(request: Request, path: str):
    session_id  = request.headers.get("x-garnet-session-id", "default")
    body        = await request.json()

    # Step 3 — pseudonymize every user message
    for msg in body["messages"]:
        msg["content"] = _pseudo_with_cache(msg["content"], session_id, enabled_types)

    # Step 4 — forward to real LLM
    response = await client.post(url, json=body, ...)

    # Step 5 — depseudonymize response
    return depseudonymize(response_text, session_id, store)
Internal requests are skipped
Requests that contain system-prompt markers (title generation, tag generation, follow-up suggestions) are detected by detect_internal_type() and passed through without pseudonymization — the LLM only sees internal Garnet prompts, no user PII.

4. How Pseudonymization Works

Three detection layers run in sequence. Each adds entities to the same result list.

Layer Library What it catches Languages
1. GLiNER gliner_multi_pii-v1 PERSON, LOCATION, ORGANIZATION — context-aware transformer Multilingual
2. Presidio presidio-analyzer + spaCy EMAIL, IBAN, PHONE, fallback NER EN + DE
3. Regex Built-in re Email, phone, IBAN — pattern-only fallback when NLP misses Any

Token generation

# Deterministic: same text always → same token within a session
token = f"PERSON_{hashlib.md5(original.encode()).hexdigest()[:8]}"

# Result stored in session mapping:
mapping["PERSON_cc75010d"] = "Max Mustermann"
Why deterministic hashing?
Same name in message 1 and message 5 gets the SAME token. The LLM sees consistent names across the conversation, so it doesn't get confused by multiple tokens for the same entity.

Cache layer

# _pseudo_with_cache() — avoid re-running NLP on the same text twice
h = hashlib.md5(text.encode()).hexdigest()
hit = session_cache.get(h)
if hit is not None:
    return hit          # skip GLiNER + Presidio entirely
out = pseudonymize(text, session_id, store, enabled_types)
session_cache[h] = out

The per-session cache (pseudo_cache) lives in memory. Each unique text is only analyzed once per session — important because chat history grows and the same messages would otherwise be re-scanned on every new turn.

5. The Mapping Store — Memory of the Proxy

The mapping store is the heart of reversibility. Without it, pseudonymization is a one-way street.

# Structure: session_id → { token: original }
store = {
  "session-abc123": {
    "PERSON_cc75010d":       "Max Mustermann",
    "ORGANIZATION_bd3a68a5": "Enclaive GmbH",
    "IBAN_CODE_f4e21a":      "DE89 3704 0044 0532 0130 00",
  }
}

Two backends

In-memory (default)
Python dict, lives in the proxy process

Fast, zero config. Lost on proxy restart. Fine for most deployments since sessions are short-lived.

Redis (optional)
Set REDIS_URL env var to enable

Mappings survive restarts. Useful for long sessions or multi-replica deployments. TTL is set to 1 hour via SETEX.

Isolation is per session_id
The session ID comes from the x-garnet-session-id header (set by Open WebUI per chat). Two users in different chats never share a mapping — their tokens stay isolated.

6. How Depseudonymization Works

After the LLM responds, the proxy runs depseudonymize() before returning anything to Open WebUI.

# depseudonymizer.py
def depseudonymize(text: str, session_id: str, store: dict) -> str:
    mapping = store.get(session_id, {})

    # safety check — did LLM accidentally reveal a real name?
    text = check_leakage(text, mapping)

    # replace tokens, longest first to avoid partial matches
    for token in sorted(mapping.keys(), key=len, reverse=True):
        text = text.replace(token, mapping[token])

    return text

Leakage detection

# If LLM says "PERSON_abc refers to Max Mustermann" → redact
LEAK_PATTERNS = ["refers to", "stands for", "is actually",
                 "real name is", "which is", "means"]

If the response contains one of these phrases AND a real value from the mapping, that real value is replaced with [REDACTED]. This prevents the LLM from "explaining" a pseudonym back to the user.

7. Streaming + Depseudo — The Tricky Part

LLMs stream responses token-by-token as text/event-stream. Tokens like PERSON_cc75 can arrive split across chunks. The proxy must buffer until a complete token is guaranteed before depseudonymizing. 

# split_at_safe_boundary() — don't flush a partial token
def split_at_safe_boundary(buffer: str):
    TOKEN_NAMES = ['PERSON', 'ORGANIZATION', 'EMAIL_ADDRESS', ...]

    # if buffer ends with "PERS" → hold it, don't flush yet
    for token in TOKEN_NAMES:
        for length in range(1, len(token) + 1):
            if buffer.endswith(token[:length]):
                safe = buffer[:-length]
                return safe, buffer[len(safe):]  # (safe_to_flush, held)

    return buffer, ""  # nothing partial — flush everything
First chunk is special
stream_with_depseudo() sends a metadata chunk first (before any LLM output) containing the pseudonymized prompt preview, entity count breakdown, and query variants. Open WebUI uses this to show the privacy sidebar.

8. Special HTTP Headers

Open WebUI and the proxy communicate extra context via custom headers. These never go to the LLM.

HeaderDirectionPurpose
x-garnet-session-id OWU → Proxy Which mapping dict to use. One per chat session.
x-garnet-user-id OWU → Proxy User identifier for logging.
x-garnet-entities OWU → Proxy Comma-separated list of entity types to enable (e.g. PERSON,EMAIL_ADDRESS). Empty = all.
x-garnet-queryexpand OWU → Proxy If true, proxy calls GPT-4o-mini to generate 3 RAG query variants before forwarding.
x-openai-base-url OWU → Proxy Where to forward the request. Proxy auto-detects self-loops and routes to the real provider.
Self-loop detection
If x-openai-base-url points back to the proxy itself (contains localhost:8080 or privacy-proxy), the proxy reads the Authorization header to figure out the real provider:

sk-ant-* → Anthropic  |  AIza* → Gemini  |  gsk-* → Groq  |  sk-or-* → OpenRouter  |  else → OpenAI

Mapping Store — How It Works in the Proxy

Where tokens are saved, how they're looked up, and how the proxy uses them to restore PII.

1. What Is the Mapping Store?

The mapping store is a dictionary that remembers which token replaced which real value. Without it, pseudonymization is a one-way street — you could never restore the original names in the response.

# Structure — one dict per session
store = {
  "session-abc123": {
    "PERSON_cc75010d":       "Max Mustermann",
    "ORGANIZATION_bd3a68a5": "Enclaive GmbH",
    "IBAN_CODE_f4e21a":      "DE89 3704 0044 0532 0130 00",
  },
  "session-xyz999": {
    "PERSON_9f3b21c0": "Anna Schmidt",
  }
}
Key idea
Each chat session has its own isolated dict. Token PERSON_cc75010d in session A means something completely different from the same token in session B — or it might not exist at all.

2. Where Is It Created?

At the top of main.py, once, when the proxy starts:

# main.py line 53 — lives for the entire process lifetime
store = MappingStore(ttl=3600)

One global store object. All requests share it. Sessions are isolated by session_id key inside it.

3. How Does the Proxy Know Which Session?

The session_id is resolved at the start of every request in proxy():

# main.py line 401
session_id = (
    body.get("chat_id")                                   # preferred — OWU sends this
    or (messages[0].get("id") if messages else None)        # fallback
    or hashlib.md5(first_msg.encode()).hexdigest()[:12]       # last resort
)

OWU always sends chat_id — one unique ID per chat conversation. That becomes the key into the mapping store.

4. When Is It Written To?

Every time pseudonymize() runs, it writes new tokens into the store for that session. This happens in two places in proxy():

4a — File content (RAG context)

# main.py line 572 — pseudonymize uploaded file text
pseudonymized_text = pseudonymize(
    content_text, session_id, store.get_store(), enabled_types=enabled_types
)
# store now contains tokens found in the file
store.get_store().flush(session_id)  # persist to Redis if configured

4b — User message (last message)

# main.py line 630 — pseudonymize the actual user prompt
pseudonymized_text = pseudonymize(
    original_content_text, session_id, store.get_store(), enabled_types=enabled_types
)
# more tokens may be added for names in the user's message
store.get_store().flush(session_id)
Snapshot trick
The proxy snapshots the keys before pseudonymizing, then checks after to count how many new tokens were added: 
existing_keys_before = set(store.get_store().get(session_id, {}).keys())
# ... pseudonymize ...
new_keys = set(store.get_store().get(session_id, {}).keys()) - existing_keys_before
file_entity_count = len(new_keys)  # shown in privacy sidebar

5. When Is It Read?

After the LLM responds, the proxy builds the full mapping for this session and passes it to the depseudonymizer:

# main.py line 729 — build session mapping before depseudo
session_mapping = dict(store.get_store().get(session_id, {}))

# also merge file mappings (uploaded files use "file:" prefix)
if privacy_enabled:
    for key, mapping in store._store.items():
        if key.startswith("file:"):
            session_mapping.update(mapping)

Why merge file mappings? Because a token like PERSON_cc75010d might have been introduced by an uploaded file, not the chat session itself. Both need to be restored in the response.

# then passed into stream_with_depseudo
return StreamingResponse(
    stream_with_depseudo(src, session_mapping, ...)
)

Inside stream_with_depseudo, every safe chunk gets tokens replaced:

for token in sorted(session_mapping.keys(), key=len, reverse=True):
    safe = safe.replace(token, session_mapping[token])
Longest first — why?
If mapping has PERSON_cc7 and PERSON_cc75010d, replacing the short one first would corrupt the long one. Sorting by length descending avoids this.

6. Full Lifecycle in One Picture

1
Request arrives
proxy() resolves session_id from chat_id
2
Pseudonymize
pseudonymize() detects PII, writes tokens → store[session_id]
3
Forward
Cleaned body sent to LLM. Store waits.
4
Depseudonymize
Read store[session_id] → replace tokens → user sees real names
TTL = 1 hour
Sessions expire after 1 hour of inactivity. After that, tokens are gone — old messages can no longer be restored. This is intentional: mappings are not permanent storage.

7. Redis — The Optional Second Backend

By default the mapping store is just a Python dict in memory. The problem: if the proxy restarts (Docker redeploy, crash), all mappings are lost. Active chats would see tokens like PERSON_cc75010d instead of real names in the response.

Redis solves this. Set one env var and the store survives restarts:

# docker-compose or k8s env
REDIS_URL=redis://localhost:6379

How it works in mapping_store.py

# on startup — connect or fall back silently
try:
    _redis_client = redis.from_url(REDIS_URL) if REDIS_URL else None
    if _redis_client: _redis_client.ping()
except:
    _redis_client = None  # Redis down → memory-only, no crash

Write — every flush() call

# when proxy calls store.get_store().flush(session_id)
_redis_client.setex(
    f"garnet:mapping:{session_id}",  # key
    3600,                             # TTL in seconds
    json.dumps(mapping)               # value — the full token dict
)

Read — when session not in memory

# proxy restarts, memory is empty, but Redis still has it
raw = _redis_client.get(f"garnet:mapping:{session_id}")
if raw:
    mapping = json.loads(raw)
    self._memory[session_id] = mapping  # restore to memory
Memory only (default)
No config needed

Fast. Lost on restart. Fine for short sessions.

Memory + Redis
Set REDIS_URL env var

Memory is the fast cache. Redis is the backup. Read from memory first, fall back to Redis only on a miss.

Redis key format
Keys follow the pattern garnet:mapping:{session_id}. File sessions use garnet:mapping:file:{file_id}. This is how the proxy separates chat mappings from file mappings in Redis.

3 · Streaming depseudonymization

🌊
stream_with_depseudo(response_stream, mapping, …)
main.py : 158–256
The heart of Garnet — reads LLM SSE chunks, replaces pseudo tokens with real names, and forwards to browser in real-time.
▸

Step 1 — metadata yield

  • Immediately sends {"type":"pseudonymized_prompt",...} — OWU reads this to show the Garnet badge with entity count

Step 2 — chunk loop

  • Receives raw bytes from LLM, splits on \n, strips data: prefix
  • Parses JSON, extracts choices[0].delta.content
  • Also captures token usage in OpenAI, Anthropic native, and Anthropic OpenAI-compat formats

Step 3 — safe depseudo per chunk

  • Appends chunk text to rolling buffer
  • Calls split_at_safe_boundary() → safe part + held remainder
  • Replaces all pseudo tokens in safe part, longest token first
  • Yields data: {"choices":[{"delta":{"content": safe}}]} to browser

Step 4 — flush + logs

  • Any leftover buffer is depseudo'd and sent after stream ends
  • Logs chunk count, total chars, TTFT, total latency, token counts, privacy audit

5 · Main proxy handler — the big one

🚀
proxy(request, path) — catches ALL routes
main.py : 347–end
Every request that isn't /health, /vault/scan, /analyze goes here. The full Garnet pipeline in one function.
▸

Block A — Route detection

  • Is the path openai/…? → flag is_openai = True
  • Is it a chat endpoint? (v1/chat/completions, api/chat…) → flag is_chat = True
  • Non-chat requests (embeddings, model list) are passed through without any PII processing

Block B — URL & provider resolution

  • If the base URL points back to the proxy itself (self-loop) → detect real provider from API key prefix
  • sk-ant- → Anthropic  |  AIza → Gemini  |  gsk- → Groq  |  sk-or- → OpenRouter
  • Sets provider_label used in logs

Block C — Session ID

  • Tries in order: body.chat_id → messages[0].id → MD5(first_message)[:12]
  • Session ID is the key linking all messages to their PII mapping store
⚠ MD5 fallback means two users saying "Hi" share a session — known bug P0-9.

Block D — Responses API remap (GPT-5 models only)

  • Converts /v1/chat/completions body → /v1/responses format
  • Moves system messages into instructions field
  • Remaps image_url → input_image, text → input_text
  • Moves response_format into text.format, reasoning_effort into reasoning.effort

Block E — History pseudonymization

  • Loops over all messages except the last one
  • Skips empty messages, OWU internal system-prompt messages, and already-pseudonymized messages
  • Calls _pseudo_with_cache() on each — GLiNER only runs on new text
  • Replaces msg["content"] in-place

Block F — RAG / file context pseudonymization

  • Scans all messages for <context> / <source / {{CONTEXT}} tags — RAG-injected document chunks
  • For large files (>50 000 chars) → splits into 10k-char overlapping chunks, pseudonymizes each, rejoins
  • Merges file mapping with chat session mapping so depseudo works across both

Block G — Last user message pseudonymization

  • Takes messages[-1] (the new user message)
  • Calls pseudonymize() directly — not cached, it's always new text
  • Stores the pseudonymized version as pseudonymized_user_message — sent to OWU for the badge
  • If nothing was replaced → logs "no PII detected"

Block H — Forward to LLM (Ollama, non-streaming)

  • Ollama returns a single JSON object (not SSE)
  • Fetches response, extracts message.content
  • Replaces all pseudo tokens with real values inline, returns modified JSON

Block I — Forward to LLM (OpenAI/cloud, streaming)

  • Opens streaming HTTP request to the provider
  • Builds session_mapping = chat mapping + all file: mappings merged
  • If stream=False → regular request, depseudo full response, return JSON
  • If streaming → passes byte generator to stream_with_depseudo(), returns StreamingResponse
