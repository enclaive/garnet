MappingStore & pseudo_cache
main.py : 53–56
Two in-memory stores that remember what PII was replaced with what token.
▸
  • store = MappingStore() — the main session→token→real-value dictionary, optionally backed by Redis

2 · Utility functions

📄
extract_text_content(content)
main.py : 59–68
Pulls plain text out of a message — handles both simple strings and OpenAI multi-part content arrays.
▸

A message content can be:

  • A plain string → return as-is
  • A list of blocks like [{"type":"text","text":"hello"}, {"type":"image_url",...}] → join all text blocks
Used everywhere before calling pseudonymize — ensures we always pass a string, not a JSON array.
🔧
rebuild_content(original_content, pseudonymized_text)
main.py : 71–82
Puts the pseudonymized text back into the original message structure without breaking image blocks.
▸

The reverse of extract_text_content. If the original was a list, it replaces only the text blocks and keeps image/file blocks untouched.

  • string → returns pseudonymized string directly
  • list → rebuilds list, swapping text blocks for the new pseudonymized version
⚡
_pseudo_with_cache(text, session_id, enabled_types)
main.py : 86–96
Runs pseudonymize() but skips re-running GLiNER/spaCy if the same text was already processed this session.
▸
  • Computes MD5(text) as cache key
  • If found in pseudo_cache[session_id] → returns cached result instantly
  • If not → calls pseudonymize(), stores result, returns it
Used for history messages — conversation history is resent every turn, so this avoids re-scanning 10 previous messages with GLiNER each time.
✂️
split_at_safe_boundary(buffer)
main.py : 99–115
Prevents a pseudo token like PERSON_abc12 from being split across two SSE stream chunks.
▸

SSE streams arrive in arbitrary chunks. If a chunk ends mid-token like "...PERSON_a" and we replace it, we'd miss the full token PERSON_abc123.

  • Checks if the buffer ends with a partial token prefix (PERSON, ORGAN…, etc.)
  • Returns (safe_part, remainder) — safe part is depseudo'd and yielded, remainder is held for next chunk
🔍
detect_internal_type(content)
main.py : 118–127
Identifies OWU auto-generated system messages so the proxy skips pseudonymizing them.
▸

OWU sends many internal messages that are not user-written text — title generators, tag generators, follow-up generators. Pseudonymizing those would break them.

  • "follow_ups" → follow_ups
  • "Generate a concise" + "title" → title_gen
  • "Generate 1-3 broad tags" → tags_gen
  • "search_query" → search_query

3 · Streaming depseudonymization

🌊
stream_with_depseudo(response_stream, mapping, …)
main.py : 158–256
The heart of Garnet — reads LLM SSE chunks, replaces pseudo tokens with real names, and forwards to browser in real-time.
▸

Step 1 — first yield (metadata)

  • Immediately sends a special {"type":"pseudonymized_prompt",...} JSON line with what the LLM will see — OWU reads this to show the Garnet badge

Step 2 — chunk loop

  • Receives raw bytes from LLM, splits on \n, strips data: prefix
  • Skips [DONE] sentinel and empty lines
  • Parses JSON to extract choices[0].delta.content text
  • Also captures token usage (input/output) from OpenAI, Anthropic native, and Anthropic OpenAI-compat formats

Step 3 — safe depseudo per chunk

  • Appends chunk text to a rolling buffer
  • Calls split_at_safe_boundary(buffer) → gets safe part + remainder held back
  • Replaces all pseudo tokens in safe part using the session mapping (longest token first to avoid partial matches)
  • Yields data: {"choices":[{"delta":{"content": safe}}]}\n\n to browser

Step 4 — flush remainder + logs

  • Any leftover buffer is depseudo'd and sent after the stream ends
  • Logs chunk count, total chars, TTFT, total latency, token counts, privacy audit

Pseudonymizes an uploaded document and stores the mapping. Called when a user uploads a file to OWU.

5 · Main proxy handler — the big one

🚀
proxy(request, path) ← catches ALL routes
main.py : 347–end
Every request that isn't /health, /vault/scan, /analyze goes here. This is the full Garnet pipeline in one function.
▸

Block A — Route detection

  • Is the path openai/…? → flag is_openai = True
  • Is it a chat endpoint? (v1/chat/completions, api/chat, etc.) → flag is_chat = True
  • Non-chat requests (embeddings, model list, etc.) are passed through without any PII processing

Block B — URL & provider resolution

  • If the base URL in the header points back to the proxy itself (self-loop) → detect real provider from API key prefix (sk-ant-→Anthropic, AIza→Gemini, gsk-→Groq)
  • Sets provider_label used in logs: openai / anthropic / groq / gemini / ollama

Block C — Session ID

  • Tries in order: body.chat_id → messages[0].id → MD5(first_message)[:12]
  • Session ID is the key that links all messages to their PII mapping store
⚠ MD5 fallback means two users saying "Hi" share a session — known bug P0-9.

Block D — Responses API remap (GPT-5 models only)

  • Converts /v1/chat/completions body format → /v1/responses format
  • Moves system messages into instructions field
  • Remaps image_url blocks to input_image, text to input_text
  • Moves response_format into text.format, reasoning_effort into reasoning.effort

Block E — History pseudonymization

  • Loops over all messages except the last one
  • Skips empty messages, system-prompt messages (OWU internal), and already-pseudonymized messages
  • Calls _pseudo_with_cache() on each — GLiNER only runs on new text
  • Replaces msg["content"] in-place with pseudonymized version

Block F — RAG / file context pseudonymization

  • Scans all messages for <context> / <source / {{CONTEXT}} tags — these are RAG-injected document chunks
  • For large files (>50 000 chars) → splits into 10k-char overlapping chunks, pseudonymizes each separately, rejoins
  • Merges file mapping with chat session mapping so depseudo works across both

Block G — Last user message pseudonymization

  • Takes messages[-1] (the new user message)
  • Calls pseudonymize() directly (not cached — it's always new text)
  • Stores the pseudonymized version in pseudonymized_user_message — sent to OWU in the response metadata so the badge shows what the LLM saw
  • If nothing was replaced → logs "no PII detected"

Block H — Forward to LLM (Ollama path, non-streaming)

  • Ollama returns a single JSON object (not SSE)
  • Fetches the response, extracts message.content
  • Replaces all pseudo tokens with real values inline
  • Returns the modified JSON directly

Block I — Forward to LLM (OpenAI/cloud path, streaming)

  • Opens a streaming HTTP request to the provider
  • Builds session_mapping = chat mapping + all file: mappings merged together
  • If stream=False was requested → does a regular request, depseudo's the full response, returns JSON
  • If streaming → passes the byte generator to stream_with_depseudo() and returns a StreamingResponse
