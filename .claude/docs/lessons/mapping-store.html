Mapping Store — Deep Dive

How the proxy remembers which token replaced which real value — memory, Redis, and the full write/read lifecycle.

What is it?

The mapping store is the memory of reversibility. When the proxy replaces "Max Mustermann" with PERSON_cc75010d, it must remember that relationship so it can swap it back in the LLM response. The mapping store holds that dictionary.

User: "Max Mustermann"
→
pseudonymize()
→
LLM: "PERSON_cc75010d"
→
mapping store lookup
→
User sees: "Max Mustermann"
# What the store looks like at runtime
store._store = {
  "chat-abc123": {
    "PERSON_cc75010d":       "Max Mustermann",
    "ORGANIZATION_bd3a68a5": "Enclaive GmbH",
    "IBAN_CODE_f4e21a":      "DE89 3704 0044 0532 0130 00",
  },
  "file:doc-xyz": {
    "PERSON_9f3b21c0": "Anna Schmidt",
  }
}
Key designOne dict per session. Sessions are isolated — two users never share tokens. File uploads get their own file:-prefixed session so they don't mix with chat sessions.

Three classes, one job

MappingStore

Top-level object. Created once at proxy startup. Owns the in-memory dict and the TTL/cleanup logic. Thread-safe via a lock.

_RedisAwareStore

Returned by get_store(). Adds Redis read/write on top of the memory dict. Memory is always checked first — Redis is the fallback.

_TrackedDict

A dict subclass. Every time pseudonymize() adds a new token via dict[key] = value, it auto-syncs back to _memory. The link between pseudonymizer and store.

_redis_client (module-level)

A redis.from_url() client created once at import time. None if REDIS_URL is not set or Redis is unreachable. All three classes share it.

Two backends, one interface

Memory only (default)

No config needed. Fast. Lost on proxy restart — active chats would see raw tokens in responses after a redeploy. Fine for short sessions.

Memory + Redis

Set REDIS_URL env var. Memory is the fast cache. Redis is the durable backup. Survives restarts. TTL = 1 hour (configurable).

RuleRead: memory first, Redis on miss. Write: memory always, Redis if available. The two stay in sync via flush().

Classes & Code

Every method explained line by line.

MappingStore — the container

class MappingStore:
    def __init__(self, ttl: int = 3600):
        self._store      = {}           # session_id → {token: real_value}
        self._timestamps = {}           # session_id → last_access time
        self._ttl        = ttl          # seconds before a session expires
        self._lock       = threading.Lock()  # one writer at a time

get_mapping(session_id)

def get_mapping(self, session_id):
    with self._lock:
        self._cleanup(session_id)               # evict if expired
        return self._store.setdefault(session_id, {})

Direct access — returns the raw dict. Only used internally. Most callers go through get_store() instead.

get_store()

def get_store(self):
    return _RedisAwareStore(self._store, self._ttl)

Creates a new _RedisAwareStore wrapper on every call (known inefficiency — P2-29 in the improvement report). The wrapper holds a reference to self._store, so writes through the wrapper go into the same dict.

Bug P2-29get_store() allocates a new _RedisAwareStore object on every call to proxy(). This is harmless but wasteful — it should cache the instance.

_cleanup(session_id)

def _cleanup(self, session_id):
    now = time.time()
    if session_id in self._timestamps:
        if now - self._timestamps[session_id] > self._ttl:
            del self._store[session_id]
            del self._timestamps[session_id]
    self._timestamps[session_id] = now     # refresh access time
Bug P0-8Only checks expiry for the session currently being accessed. Dead sessions from other users accumulate forever until they happen to be accessed again. Under traffic, this leaks memory unboundedly.

_RedisAwareStore — the smart wrapper

This is the object proxy() actually works with. It looks like a dict but transparently adds Redis reads and writes.

get(session_id) — read with Redis fallback

def get(self, session_id, default=None):
    # 1. check memory first — fastest path
    if session_id in self._memory:
        return self._memory[session_id]

    # 2. memory miss → try Redis
    if _redis_client:
        raw = _redis_client.get(f"garnet:mapping:{session_id}")
        if raw:
            mapping = json.loads(raw)
            self._memory[session_id] = mapping   # warm the cache
            return mapping

    return default

__setitem__(session_id, mapping) — write to both

def __setitem__(self, session_id, mapping):
    self._memory[session_id] = mapping          # always write memory
    if _redis_client:
        _redis_client.setex(
            f"garnet:mapping:{session_id}",
            self._ttl,                           # TTL in seconds
            json.dumps(mapping)
        )

setdefault(session_id) — get or create, return TrackedDict

def setdefault(self, session_id, default=None):
    existing = self.get(session_id)
    if existing is not None:
        return _TrackedDict(session_id, existing, self)  # wrap existing
    value = default if default is not None else {}
    self[session_id] = value
    return _TrackedDict(session_id, value, self)         # wrap new

Called by pseudonymize() internally to get a writable dict for the session. Returns a _TrackedDict so every token write auto-syncs back to memory.

flush(session_id) — force sync to Redis

def flush(self, session_id):
    if _redis_client and session_id in self._memory:
        _redis_client.setex(
            f"garnet:mapping:{session_id}",
            self._ttl,
            json.dumps(self._memory[session_id])
        )

Called by proxy() explicitly after pseudonymization is done to make sure Redis has the latest snapshot. __setitem__ also writes to Redis, but flush() is the guaranteed "everything is settled now" sync.

_TrackedDict — the auto-sync wrapper

class _TrackedDict(dict):
    def __init__(self, session_id, data, store):
        super().__init__(data)
        self._session_id = session_id
        self._store = store

    def __setitem__(self, key, value):
        super().__setitem__(key, value)
        self._store._memory[self._session_id] = dict(self)  # sync to memory

    def flush(self):
        self._store.flush(self._session_id)  # push to Redis

_TrackedDict is what pseudonymize() writes into. Every time it does mapping["PERSON_abc"] = "Max", the __setitem__ override also updates _memory[session_id]. This is the glue between the pseudonymizer and the store.

Bug P1-18Line self._store._memory[self._session_id] = dict(self) allocates a full new dict copy on every single token write. Since _memory[session_id] and self already point to the same underlying data, this is redundant. It's dead-weight allocation on every entity found.

Redis — How It Fits In

When it connects, what keys it uses, when it reads and writes, and what happens without it.

Connection — module load time

# mapping_store.py — runs once when the module is imported
try:
    import redis
    REDIS_URL = os.getenv("REDIS_URL")
    _redis_client = redis.from_url(REDIS_URL) if REDIS_URL else None
    if _redis_client:
        _redis_client.ping()
        print("[MAPPING STORE] Redis connected")
except Exception as e:
    print(f"[MAPPING STORE] Redis unavailable: {e}")
    _redis_client = None   # silently degrade to memory-only
Graceful degradationIf Redis is down or REDIS_URL is not set, _redis_client = None and every Redis path is skipped. The proxy runs fine in memory-only mode — you only lose persistence across restarts.
Bug P0-1redis.from_url() returns a synchronous client. Every .get() / .setex() call blocks the asyncio event loop. Under load (or Redis latency), this freezes all in-flight requests until the Redis round-trip completes. Fix: swap to redis.asyncio.from_url().

Key naming convention

Session typeRedis key patternExample
Chat sessiongarnet:mapping:{session_id}garnet:mapping:chat-abc123
Uploaded filegarnet:mapping:file:{file_id}garnet:mapping:file:doc-xyz

The value is json.dumps({"PERSON_cc75010d": "Max Mustermann", ...}) — the full token→real-value dict stored as a JSON string.

TTL is set on every write via SETEX (set + expire). Default: 3600 seconds (1 hour). Every write resets the clock.

When Redis is read

Only on a memory miss inside _RedisAwareStore.get():

# Scenario: proxy restarts → memory is empty → user sends a message in an old chat
session_id = "chat-abc123"

# memory check fails (empty after restart)
if session_id in self._memory:   # → False
    ...

# Redis fallback
raw = _redis_client.get("garnet:mapping:chat-abc123")
# → b'{"PERSON_cc75010d": "Max Mustermann", ...}'

mapping = json.loads(raw)
self._memory[session_id] = mapping   # restore to memory cache
# next call hits memory — Redis not touched again for this session
Memory as cacheAfter one Redis read, the mapping lives in memory. Subsequent requests for the same session never touch Redis again (unless the proxy restarts).

When Redis is written

Two paths write to Redis:

1 — __setitem__ (immediate write)

# triggered when proxy does: store.get_store()[session_id] = mapping
_redis_client.setex(f"garnet:mapping:{session_id}", ttl, json.dumps(mapping))

2 — flush() (explicit sync after pseudonymization)

# called in proxy() after pseudonymize() finishes writing tokens
store.get_store().flush(session_id)
# → setex("garnet:mapping:chat-abc123", 3600, '{"PERSON_cc75010d":"Max",...}')
Why two write paths?__setitem__ fires when the whole mapping dict is assigned at once. flush() fires after individual token writes through _TrackedDict — those go to memory only, so flush() is needed to push the final snapshot to Redis.

File upload vs chat session — how they merge

When a user uploads a file, OWU calls POST /vault/scan. The proxy pseudonymizes the file with session_id = "file:{file_id}". That mapping is stored separately.

Later, when the user chats about the file, the proxy merges both:

# Chat session has: {"PERSON_cc75": "Max"}
# File session has: {"ORGANIZATION_bd3a": "Enclaive GmbH", "IBAN_CODE_f4": "DE89..."}

session_mapping = {"PERSON_cc75": "Max"}          # from chat session
session_mapping.update({
    "ORGANIZATION_bd3a": "Enclaive GmbH",        # from file:doc-xyz
    "IBAN_CODE_f4": "DE89 3704...",
})
# now depseudo can restore everything in the LLM response
Why separate?File mappings are permanent for the file's lifetime. Chat mappings expire per session. Keeping them separate means a reuploaded file doesn't reset a chat session's TTL.

How pseudonymize() writes tokens

Inside pseudonymizer.py, the store is passed as a plain dict reference. Every entity found gets written like:

# pseudonymizer.py (simplified)
mapping = store.setdefault(session_id, {})   # returns _TrackedDict
token = f"PERSON_{hashlib.md5(original.encode()).hexdigest()[:8]}"
mapping[token] = original                    # _TrackedDict.__setitem__ fires
# → self._store._memory[session_id] updated immediately

The _TrackedDict is the bridge — pseudonymizer thinks it's writing to a plain dict, but every write auto-propagates to the store's memory layer.

Known Bugs in the Store

All open issues from the 2026-08-22 improvement report that touch mapping_store.py.

P0 — Critical

P0-1 Sync Redis client blocks async event loop

redis.from_url() returns a synchronous client. Every .get() / .setex() blocks the uvicorn event loop for the full Redis round-trip. With --workers 1, one slow Redis call freezes every other in-flight request. Root cause of the "stuck after 5 prompts" symptom.

Fix: swap to redis.asyncio.from_url(), make get() / flush() / __setitem__ async.

P0-8 MappingStore memory leak — dead sessions never swept

_cleanup(session_id) only checks expiry for the session being accessed right now. Sessions from other users accumulate in self._store forever. Under sustained traffic, the proxy OOMKills on k8s.

Fix: in _cleanup, sweep all expired sessions, not just the current one: 

now = time.time()
expired = [sid for sid, ts in self._timestamps.items() if now - ts > self._ttl]
for sid in expired:
    del self._store[sid]; del self._timestamps[sid]

P0-10 Redis stores plaintext PII + swallows write errors silently

json.dumps(mapping) written raw to Redis — a Redis breach = full PII disclosure. All Redis errors are caught by bare except Exception and printed — a failed write means depseudo will fail later but the proxy doesn't know it.

Fix: Fernet-encrypt before setex. Narrow except to redis.RedisError and re-raise or flag.

P0-12 KEYS command on Redis every chat turn

_redis_client.keys("garnet:mapping:file:*") called in proxy() on every follow-up message. KEYS is O(N over all keys in Redis) and blocks Redis itself. With any real user load, this causes Redis stalls visible as "stuck" to all users simultaneously.

Fix (quick): replace with scan_iter(match=..., count=200) — non-blocking. Fix (proper): maintain a Redis SET garnet:file_sessions and do a single SMEMBERS.

P1 / P2 — Worth fixing

P1-18 _TrackedDict.__setitem__ copies whole dict on every token write

self._store._memory[self._session_id] = dict(self) — a full dict copy on every entity. Since _memory[session_id] and self are already the same object (set via setdefault), this is both redundant and slow. An entity-heavy document triggers dozens of copies.

Fix: delete lines 110–111. The sync is already implicit — _memory[session_id] IS self.

P2-29 get_store() allocates new _RedisAwareStore per call

Called from every code path in proxy() — typically 3-5 times per request. Each call creates a new wrapper object for no reason.

Fix: cache the instance in __init__.

P1-16 session_mapping scan for file: sessions on every request

for key, mapping in store._store.items(): if key.startswith("file:") — iterates every in-memory session on every chat message. As dead sessions accumulate (P0-8 unfixed), this is O(n_sessions) per request.

Fix: maintain a file_session_index: set[str] on MappingStore, updated on file scan / eviction. Iterate only that set.
