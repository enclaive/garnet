1. Overview & big picture

The Garnet proxy sits between OWU and every LLM provider. It has one HTTP handler that receives every request and routes it based on three signals:

  1. Incoming path — /openai/*, /ollama/*, etc. → tells us which provider bucket.
  2. URL substring match — api.openai.com, anthropic.com, groq.com, etc. → provider-specific handling.
  3. Model name — gpt-image-1, gpt-5.5-pro, etc. → model-specific exceptions.
Browser → OWU (chat/completions) → Garnet Proxy → Provider │ ├─ pseudonymize PII ├─ classify path + provider + model ├─ transform body per provider/model ├─ stream response └─ depseudonymize on the way back

4. Local vs external providers

Local (Ollama)

Ollama runs in the same Docker network as the proxy (garnet-ollama-1, port 11434). Key characteristics:

  • Uses OLLAMA_URL env var (default http://localhost:11434).
  • Response format is different from OpenAI — Ollama returns {message:{content}} not {choices:[{message:{content}}]}.
  • Forced to non-streaming for the depseudo path: body["stream"] = False when not OpenAI.
  • Response body is inspected as a single JSON blob; PII tokens replaced in message.content.

External (OpenAI, Anthropic, Groq, Gemini, Mistral)

  • Uses HTTPS to the provider's public API.
  • Streaming with aiter_bytes() — arbitrary byte chunks yielded through so line-length limits don't trigger.
  • Depseudonymization done on-the-fly by parsing SSE events.
  • Each provider has its own auth header (Anthropic gets anthropic-version: 2023-06-01).
Why aiter_bytes for all providers? Older code used aiter_lines() which has a 131072-byte line limit and rejects Mistral's chunked encoding. Switching to aiter_bytes() fixed Mistral TransferEncodingError and image gen line-length crashes in one change.

5. Step 3: Model-based exceptions

Some models can't use the standard chat/completions path. The proxy checks the model name and reroutes.

5.1 Image models

IMAGE_MODELS = ["dall-e-3", "dall-e-2", "gpt-image-1"]

# Path A: chat request with image model → convert to image generation call
if body and body.get("model") in IMAGE_MODELS \
   and "images/generations" not in actual_path:
    url = f"{openai_url}/images/generations"
    # Call OpenAI images API, wrap result as SSE chat response
Guard: "images/generations" not in actual_path — added in 842c01790. Prevents intercepting OWU's direct call to /v1/images/generations. Without this guard, OWU expected JSON but got SSE → aiohttp crashed on 131072-byte lines.

5.2 Responses API models (gpt-5.5-pro)

Base models like gpt-5.5-pro don't support /v1/chat/completions. The proxy reroutes them to /v1/responses:

RESPONSES_API_MODELS = {"gpt-5.5-pro"}

if is_openai and model in RESPONSES_API_MODELS:
    url = url.replace("/v1/chat/completions", "/v1/responses")
    # Body conversion: messages → input, system → instructions
    # max_tokens → max_output_tokens
    # Strip: stream_options, top_p, freq/pres penalty, logprobs, tools, tool_choice
    # SSE adapter converts response.output_text.delta → chat/completions format

5.3 OpenAI-specific body cleanups

if is_openai and "api.openai.com" in url:
    if "max_tokens" in body:
        body["max_completion_tokens"] = body.pop("max_tokens")
    if body.get("tools") and "reasoning_effort" in body:
        body.pop("reasoning_effort")
  • max_tokens → max_completion_tokens — required for reasoning models (o1, o3, o4) and newer chat models.
  • reasoning_effort stripped when tools present — gpt-5.6-luna and similar reject this combo on chat/completions with error "Function tools with reasoning_effort are not supported".

7. Step 5: Streaming vs non-streaming

Streaming path (default for OpenAI)

async def response_stream():
    async with httpx.AsyncClient() as client:
        async with client.stream(method=request.method, url=url, ...) as resp:
            async for chunk in resp.aiter_bytes():   # bytes, not lines!
                yield chunk

return StreamingResponse(
    stream_with_depseudo(response_stream(), session_mapping, ...),
    media_type="text/event-stream",
)

Non-streaming path

Triggered when body["stream"] == False — used by OWU for query generation, title generation, tag generation, and Ollama chat:

if not body.get("stream", True):
    _resp = await client.request(url=url, json=body, ...)
    result = _resp.json()
    content = result["choices"][0]["message"]["content"]
    # PII token → real value replacement
    for token in sorted(session_mapping.keys(), key=len, reverse=True):
        content = content.replace(token, session_mapping[token])
    result["choices"][0]["message"]["content"] = content
    return ORJSONResponse(content=result)

8. Step 6: Depseudonymization

Every response passes through stream_with_depseudo() which:

  • Parses SSE events (data: {...}\n\n) from the raw byte stream.
  • Extracts choices[0].delta.content.
  • Replaces every PII token (PERSON_abc123) with the real value from session_mapping.
  • Re-emits the SSE event with the depseudonymized content.
  • Passes non-content events (tool calls, deltas without content) through unchanged.
Session isolation: Each user session has its own session_mapping. Tokens generated in session A can't be leaked into session B, because depseudo only uses the current session's map.
