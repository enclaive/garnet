Garnet — Image Generation Handling

Two image paths

Path A — Chat with image model via proxy

1
User types a prompt in OWU chat with an image model selected (gpt-image-1, dall-e-3, dall-e-2).
2
OWU sends POST /openai/chat/completions to the proxy with the messages array.
3
Proxy detects model in IMAGE_MODELS and path is not images/generations → intercepts.
4
Proxy extracts the last user message as prompt, calls POST /v1/images/generations on OpenAI.
5
Proxy gets back URL or b64_json, wraps result as SSE chat stream, returns to OWU.
6
OWU renders ![image](...) markdown → image appears in chat bubble.

Path B — OWU Image Generation panel direct

1
User opens OWU's built-in image generation panel (not the chat).
2
OWU calls POST /openai/v1/images/generations directly (expects a JSON response, not SSE).
3
Proxy receives the call. actual_path = "v1/images/generations".
4
Path A guard fires: "images/generations" in actual_path → skips image intercept.
5
Proxy forwards request as-is to OpenAI and returns raw JSON to OWU.
6
OWU's panel displays the image using its own rendering logic.

Model detection — IMAGE_MODELS constant

IMAGE_MODELS = ["dall-e-3", "dall-e-2", "gpt-image-1"]

Any model in this list triggers Path A interception only when the request path is not images/generations. Adding a new image model: append to this list in backend/privacy_proxy/app/main.py.

Path A guard (the key condition)

proxy/main.py — intercept condition
if body and body.get("model") in IMAGE_MODELS and "images/generations" not in actual_path:

Why both conditions?
Without the actual_path guard, Path A would also intercept OWU's own /v1/images/generations call (Path B), returning SSE where OWU expected JSON. OWU would receive a streaming response it cannot parse → broken image panel + 400 errors.

Bugs fixed & why

Bug 1 — Text flash before image

OWU received multiple SSE delta events. The first delta contained role: assistant only (no content), causing OWU to flash an empty text bubble. Subsequent deltas with the image markdown arrived late.

Root cause: proxy was sending two separate delta events — one for role, one for content.

Fix 1 — Single delta event

Merged role and content into a single SSE delta so OWU renders the image immediately on first event with no flash.

delta = {"role": "assistant", "content": "![image](url)"}

Bug 2 — Path A intercepting Path B

OWU's image generation panel calls POST /v1/images/generations directly and expects a JSON response. Without a guard, Path A would intercept this call too, wrapping the result as SSE. OWU tried to parse SSE as JSON → 400 error / broken panel.

Symptom: image panel worked, chat worked, but both at the same time caused double-processing.

Fix 2 — actual_path guard

Added "images/generations" not in actual_path to the intercept condition. Path B now passes through the proxy as a transparent forward, returning raw JSON to OWU's panel.

if model in IMAGE_MODELS and\n   "images/generations" not in actual_path:

Bug 3 — 131072-byte SSE line limit

OWU uses aiohttp to stream from the proxy. aiohttp reads SSE line-by-line with a hard 131072-byte limit.

gpt-image-1 returns b64_json — a 1024×1024 image is ~1.5 MB of base64. Embedding this in one data: …\n\n line caused aiohttp to crash with:

Got more than 131072 bytes when reading

Fix 3 — 50 KB SSE chunks

Content is now split into 50 KB chunks, each sent as a separate SSE delta event. OWU concatenates the deltas client-side and renders the complete image when the stream finishes.

def _image_sse_chunks(text, chunk=50_000):
    yield first_delta(text[:chunk])
    for i in range(chunk, len(text), chunk):
        yield delta(text[i:i+chunk])
    yield b"data: [DONE]\n\n"

Path A — full code path in proxy/main.py

# 1. Catch-all route receives the request
@app.api_route("/{path:path}", ...)
async def proxy(request, path):
    is_openai = path.startswith("openai/")
    actual_path = path[len("openai/"):] if is_openai else path

    # 2. Path A guard — image model + not a direct /images/generations call
    if body and body.get("model") in IMAGE_MODELS and "images/generations" not in actual_path:

        # 3. Extract prompt from last user message
        url = f"{openai_url}/images/generations"
        prompt = last_user_text(body["messages"])

        # 4. Call OpenAI image API
        response = await client.post(url, json={"model": model, "prompt": prompt, "n": 1, "size": "1024x1024"})
        data = response.json()["data"][0]

        # 5. Get URL or fall back to b64
        img_url = data.get("url") or f"data:image/png;base64,{data['b64_json']}"
        content  = f"![image]({img_url})"

        # 6. Stream as 50 KB SSE chunks (safe for aiohttp line limit)
        return StreamingResponse(_image_sse_chunks(content), media_type="text/event-stream")
