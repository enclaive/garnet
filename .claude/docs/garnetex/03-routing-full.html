Phase 2 — User sends a message: OWU routing decision

Cloud path (openai.py)
1

Read urlIdx from model

idx = model['urlIdx']

2

Pick destination URL

url = os.environ.get("FORCE_OPENAI_BASE_URL")
    or OPENAI_API_BASE_URLS[idx]

If FORCE_OPENAI_BASE_URL is set → proxy.
If not set → real provider directly. No privacy filter.

3

Pick key (never overridden)

key = OPENAI_API_KEYS[idx]
Key always comes from arrays[idx], regardless of FORCE_OPENAI_BASE_URL.

4

Inject chat_id + build headers

payload['chat_id'] = metadata.get('chat_id')
headers['Authorization'] = 'Bearer ' + key
headers['x-openai-base-url'] = OPENAI_API_BASE_URLS[idx] ← real provider, sent as header to proxy
headers['x-garnet-entities'] = selected_entity_types
headers['x-garnet-queryexpand'] = "true"/"false"

5

Send to proxy

POST http://privacy-proxy:8080/openai/v1/chat/completions

Local path (ollama.py)
1

Pick Ollama URL

force_url = os.environ.get('FORCE_OLLAMA_BASE_URL')
chat_url = force_url + '/api/chat'
        or ollama_url + '/api/chat'

2

Inject chat_id

payload['chat_id'] = metadata.get('chat_id', '')

3

Add Garnet headers (only if forced)

if force_url:
  x-garnet-entities: ...
  x-openai-base-url: <original ollama url>

4

Send to proxy

POST http://privacy-proxy:8080/api/chat

Phase 3 — Proxy classifies and prepares

1

Catch-all route — single function handles everything

@app.api_route("/{path:path}") — main.py line 331
Handles GET, POST, PUT, DELETE. Non-chat routes (models list, etc.) pass through without modification.

2

Classify path

is_openai = path.startswith("openai/")
actual_path = path[len("openai/"):] # strips "openai/" prefix
is_chat = actual_path in ("v1/chat/completions", "api/chat", "v1/completions", "chat/completions")
Cloud → is_openai=True  |  Local → is_openai=False

3

Pop privacy toggle from body

privacy_enabled = body.pop("privacy_proxy", True) — main.py line 351
Removed before forwarding — LLMs don't know this field exists.
Default: True (privacy on unless explicitly disabled).

4

Build session_id

session_id = chat_id or messages[0].get("id") or md5(first_msg)[:12]
Then: body.pop("chat_id", None) — also removed before forwarding.
Falls back to "default" if all three are empty.

5

Resolve real provider URL (cloud only)

openai_url = headers.get("x-openai-base-url", OPENAI_API_URL)
Self-loop check: if URL points back at proxy → re-detect from API key prefix:
sk-ant- → Anthropic  |  gsk- → Groq  |  AIza/gemini → Gemini  |  sk-or- → OpenRouter  |  else → OpenAI
Final URL: url = f"{openai_url.rstrip('/')}/{actual_path}"

6

Fix stream mode

Cloud → keep caller's preference. If caller didn't specify → default True.
Code: body["stream"] = caller_wants_stream if caller_wants_stream is False else True
Ollama → always force stream=False — proxy needs full response to depseudonymize before returning.

7

Detect provider label (for logging)

Checks the resolved URL for keywords:
"groq" → groq  |  "gemini"/"googleapis" → gemini  |  "ollama"/"11434" → ollama  |  "anthropic" → anthropic  |  else → openai

Phase 4 — Pseudonymization pipeline

1

History messages (all except last)

MD5 cache per session — same text seen before → instant return, no re-processing.
System prompts skipped — markers checked: ### Task:, ### Guidelines:, ### Output:, JSON format:, follow_ups, Generate, Suggest
Only runs if privacy_enabled = True.

2

File / RAG context — detected across ALL messages

Any message (not just last) with <context>, <source, or {{CONTEXT}} → pseudonymized under file: session key.
Files >50k chars: chunked (10k chunks, 200 char overlap).
Entity count stored in file_entity_count — sent back in first SSE chunk so OWU sidebar can show stats.
After file scan: store.flush(session_id) to persist mappings immediately.

3

Last message — system prompt detection

Before pseudonymizing, check if it's an internal OWU system prompt.
is_system_prompt = not has_rag_context and any(marker in text for marker in SYSTEM_PROMPT_MARKERS)
If yes → skip pseudonymization, log as internal type (follow_ups, title_gen, tags_gen, search_query), also disables Responses API path.

4

Last message — actual user question

Role must be user, system, or developer.
1. Run pseudonymize() on the text → spaCy NER → EMAIL + PHONE regex → PERSON, ORG, IBAN, LOCATION, ID
2. Filter overlaps → replace → TYPE_hash[:8] token
3. Store token → original in MappingStore[session_id]
4. store.flush(session_id) to persist

5

Query expansion (optional, RAG only)

Triggered by x-garnet-queryexpand: true header AND has_rag_context = True.
Calls gpt-4o-mini to generate 3 alternative search queries.
Appends variants to pseudonymized message → richer embedding vector for Chroma retrieval.
Note: variants are NOT pseudonymized — they go to the embedding model only, not the main LLM. Known minor leak vector.
Variants returned in first SSE chunk as query_variants: [...].

Phase 5 — Forward to LLM + depseudonymize response

Correction from previous version: Phase 5 does NOT forward only authorization and content-type. The actual forwarded headers (main.py line 600) are:
authorization, content-type, openai-organization, x-openai-base-url
For Anthropic: authorization is stripped, replaced with x-api-key + anthropic-version: 2023-06-01.
Cloud — streaming (default)
1

Build forward headers

Keep: authorization, content-type, openai-organization, x-openai-base-url
Anthropic: swap Bearer sk-ant-… → x-api-key: sk-ant-… + add anthropic-version: 2023-06-01

2

Build session mapping

session_mapping = dict(store.get(session_id))
If privacy_enabled: merge all file:* mappings in — so file tokens get restored too.

3

First yield — metadata chunk

{ type: "pseudonymized_prompt", content: "...", file_entity_count: N, garnet_breakdown: {...}, query_variants: [...] }
OWU reads this to populate the Garnet sidebar stats panel.

4

Stream + safe boundary split

Buffer accumulates tokens. split_at_safe_boundary() checks if buffer ends with a partial token name (e.g. PERSO or PERSON_cc7). Holds remainder back, flushes safe prefix only.

5

Replace tokens → real values

Longest tokens first → safe.replace(token, mapping[token])
Yield as SSE: data: {"choices":[{"delta":{"content": safe}}]}\n\n
User sees real names throughout the stream, not at the end.

6

Flush remainder + DONE

After stream ends: depseudo any remaining buffer → yield → data: [DONE]

Cloud — non-streaming (stream=false)
1

Await full response

When caller explicitly sends stream: false, proxy uses a blocking request (main.py line 719):
_resp = await _client.request(..., timeout=60.0)

2

Depseudo in-place

content = result["choices"][0]["message"]["content"]
Replace all tokens → return full JSON response directly (no SSE, no metadata chunk).

Ollama — always sync
1

POST, await full response

POST http://ollama:11434/api/chat
No streaming — stream was forced to False in Phase 3.

2

Merge file: mappings + replace

content = result["message"]["content"]
Merge session + all file: mappings → replace longest first → return full JSON.
Also injects pseudonymized_prompt and file_entity_count into the result.

Special paths — not all requests go through the main pipeline

Image generation NEW

Models: dall-e-3, dall-e-2, gpt-image-1

Proxy detects these models, reroutes to:
/images/generations

Extracts the last user message as prompt, builds a minimal body:
{ model, prompt, n:1, size:"1024x1024" }

No pseudonymization on the prompt — image gen requests pass through as-is.
Returns raw provider response.

Responses API (gpt-5.5+) NEW

Models configured in env var RESPONSES_API_MODELS (default: gpt-5.5, gpt-5.5-pro and variants).

Proxy detects model → reformats body from chat format to Responses API format:
· System messages → body["instructions"]
· Other messages → body["input"]
· max_tokens → max_output_tokens
· Route: /v1/responses instead of /v1/chat/completions

Streaming depseudo uses response.output_text.delta event type.

/vault/scan — file pre-scan NEW

Called by OWU when a file is uploaded, BEFORE any chat request.

POST /vault/scan body: { text, file_id, privacy_proxy }

Pseudonymizes the file text under session key file:{file_id}.
Returns: { pseudonymized_text, entity_count, entity_breakdown, preview }

This pre-populates the mapping store so the proxy already knows all file tokens before the user asks their first question.
If privacy_proxy: false → returns text unchanged.

/analyze — entity preview NEW

Called by OWU to show which entities would be detected, without actually pseudonymizing anything.

POST /analyze body: { text, language }

Respects x-garnet-entities header to filter entity types.
Returns: { entities: [{type, value, start, end}...] }

Used by the Garnet sidebar to preview detected PII before sending.

/health

GET /health → { "status": "ok" }

Used by Docker healthcheck and k8s liveness probe.

/openai/api/tags — Ollama model list

Proxies GET /api/tags to Ollama.

OWU calls this to discover available local models.
Proxy just passes it through — no pseudonymization.

What if the proxy is disabled? — Two different scenarios

These are not the same thing. "Proxy off" can mean two completely different situations with completely different behaviour. Read both.
Scenario A — UI toggle off (privacy_proxy: false in body)

What changes

The user or admin toggled privacy off for this session.
OWU adds privacy_proxy: false to the request body.


In the proxy (main.py line 351):
privacy_enabled = body.pop("privacy_proxy", True)
→ False

What the proxy skips

  • History pseudonymization → skipped
  • File/RAG pseudonymization → skipped
  • Last message pseudonymization → skipped
  • File mapping merge in session_mapping → skipped
  • vault/scan also skips if privacy_proxy: false

What stays the same

Request still goes through the proxy.
FORCE_OPENAI_BASE_URL is still set. Routing doesn't change.

Proxy becomes a transparent forwarder — same path, no PII filtering.
Real names reach the LLM.

USER sends: "What about Max Mustermann?"
    ↓
OWU adds privacy_proxy: false to body
    ↓
Proxy privacy_enabled = False → skips all pseudonymization
    ↓
LLM receives: "What about Max Mustermann?" ← real name exposed
    ↓
LLM responds with real name (no tokens to swap back)
    ↓
USER sees: "Max Mustermann is..." ← works, but no privacy
Scenario B — FORCE_OPENAI_BASE_URL not set (proxy bypassed entirely)

What changes

The env var FORCE_OPENAI_BASE_URL is not set in docker-compose.

openai.py:
url = os.environ.get("FORCE_OPENAI_BASE_URL")
    or OPENAI_API_BASE_URLS[idx]

→ None or "https://api.anthropic.com/v1"
→ OWU sends directly to Anthropic.

Proxy is never called

The proxy container may still be running but OWU never calls it.

x-openai-base-url header is still set by OWU but it goes to the real provider — and the provider ignores it.

Same for Ollama

ollama.py:
force_url = os.environ.get('FORCE_OLLAMA_BASE_URL')
→ None
chat_url = ollama_url + '/api/chat'

Goes straight to Ollama. No garnet headers added.

USER sends: "What about Max Mustermann?"
    ↓
OWU FORCE_OPENAI_BASE_URL = None → url = "https://api.anthropic.com/v1"
    ↓ (proxy never contacted)
Anthropic receives: "What about Max Mustermann?" ← real name in cloud
    ↓
USER sees: "Max Mustermann is..."

How workload-manager.yaml injects env vars

Key mechanism: When privacyProxy.enabled: true in Helm values, workload-manager.yaml automatically overrides four env vars on the Open WebUI container — regardless of what ollamaUrls or openaiBaseApiUrl are set to. This is what forces ALL traffic through the proxy.
1

Helm renders garnet.privacyProxyUrl

{{ include "garnet.privacyProxyUrl" . }}
Helper in _helpers.tpl: http://<fullname>-privacy-proxy:8080
With release name garnet → http://garnet-privacy-proxy:8080

2

workload-manager.yaml injects 4 env vars (lines ~112–119)

{{- if .Values.privacyProxy.enabled }}
- name: "OLLAMA_BASE_URLS"
  value: http://garnet-privacy-proxy:8080
- name: "OPENAI_API_BASE_URL"
  value: http://garnet-privacy-proxy:8080/openai
- name: "FORCE_OLLAMA_BASE_URL"
  value: http://garnet-privacy-proxy:8080
- name: "FORCE_OPENAI_BASE_URL"
  value: http://garnet-privacy-proxy:8080/openai
{{- end }}
3

Why FORCE_* and BASE_URL both?

OLLAMA_BASE_URLS / OPENAI_API_BASE_URL → sets the default URL in OWU settings UI.
FORCE_OLLAMA_BASE_URL / FORCE_OPENAI_BASE_URL → locks it — even if an admin tries to change the URL in the UI, the FORCE var overrides it at request time.
Result: no path exists to bypass the proxy at runtime.
