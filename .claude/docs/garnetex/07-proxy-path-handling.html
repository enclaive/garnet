Garnet — Proxy Path Handling

Every path the proxy receives · all providers · local and cloud · special cases (Responses API, images, system prompts)

Single entry point — catch-all route

# main.py line 331 — ONE function handles everything
@app.api_route("/{path:path}", methods=["GET", "POST", "PUT", "DELETE"])
async def proxy(request: Request, path: str):
  is_openai = path.startswith("openai/") # cloud or local?
  actual_path = path[len("openai/"):] if is_openai else path
  is_chat = actual_path in ("v1/chat/completions", "api/chat", "v1/completions", "chat/completions")
⚠️ Route order matters. /analyze and /health and GET /openai/api/tags are defined BEFORE this catch-all. Anything defined after it gets a 405 — never add routes below line 331.

Step 2 — cloud only: which provider?

1

Read x-openai-base-url header

OWU injects this: x-openai-base-url: https://api.anthropic.com/v1
Proxy reads: openai_url = request.headers.get("x-openai-base-url", OPENAI_API_URL)

2

Self-loop check

If URL contains privacy-proxy or localhost:8080 → it's pointing back at itself.
Detect real provider from API key prefix instead:

3

Key prefix → provider URL

sk-ant- → https://api.anthropic.com/v1
AIza or model contains gemini → https://generativelanguage.googleapis.com/v1beta/openai
gsk- or model contains groq → https://api.groq.com/openai/v1
sk-or- → https://openrouter.ai/api/v1
anything else → https://api.openai.com/v1

4

Build final URL

url = f"{openai_url.rstrip('/')}/{actual_path}"

if use_responses_api and is_openai:

System prompt detected → Responses API cancelled. If OWU sends an internal prompt (title generation, follow-ups, etc.), use_responses_api = False and URL reverts to actual_path. This avoids sending OWU internals through the Responses API format.

Step 4 — stream mode decision

Path type stream value sent to LLM Why
Cloud chat (is_openai=True, is_chat=True) Keep caller's preference (default true) Streaming works end-to-end for cloud — depseudo happens chunk by chunk
Ollama chat (is_openai=False, is_chat=True) Always forced to False Proxy must read the full response to depseudonymize before returning. Never remove this.
Non-chat (models list, etc.) Not modified Passthrough — no pseudonymization needed
Image generation Not modified (sync only) Images API doesn't stream

Step 5 — headers forwarded to provider

Cloud (OpenAI / Groq / Gemini / OpenRouter)
# Forward only these headers
forward_headers = {
  "authorization",
  "content-type",
  "openai-organization",
  "x-openai-base-url"
}
Anthropic special case
# Convert auth format
if "anthropic.com" in url:
  auth = headers.pop("authorization")
  api_key = auth.removeprefix("Bearer ")
  headers["x-api-key"] = api_key
  headers["anthropic-version"] = "2023-06-01"

Ollama — no headers forwarded

forward_headers = {} — Ollama runs locally, no auth needed. All OWU headers stripped.

Step 6 — response handling

A

Ollama chat (is_chat + not is_openai)

Sync POST → full JSON response
Depseudo: result["message"]["content"] — replace all tokens longest-first
Merge session + file: mappings
Return: ORJSONResponse with pseudonymized_prompt + file_entity_count + query_variants added

B

Cloud chat — stream=False

Sync _client.request() → full JSON
Depseudo: result["choices"][0]["message"]["content"]
Return: ORJSONResponse

C

Cloud chat — stream=True (default)

StreamingResponse via stream_with_depseudo()
First yield: metadata chunk { type: "pseudonymized_prompt", file_entity_count, ... }
Then: buffer SSE chunks → split_at_safe_boundary() holds partial tokens → replace → yield
Depseudo longest token first throughout the stream

D

Image generation

Sync POST to /images/generations
No pseudonymization of response (it's a URL, not text)
Return raw response as-is

E

Non-chat passthrough (GET models, etc.)

Falls through all is_chat blocks
Final httpx.request() at bottom of function → return raw response
No pseudonymization

Anthropic via OpenAI-compat path — what we lose

We use the OpenAI-compatible path for Anthropic (/v1/chat/completions). Anthropic says this path is for testing only, not production. Features lost:

Lost features

  • Prompt caching (would reduce cost 80%+)
  • Extended thinking / reasoning effort
  • PDF processing + citations
  • Guaranteed tool-use schema conformance

What works fine

  • Standard chat completions
  • Streaming
  • Function / tool calling (basic)
  • All Claude models (Opus, Sonnet, Haiku)

Fix: native Anthropic API

Would require integrating /v1/messages natively in the proxy — different request/response format.

Needs Seb approval before implementing.

Example 1 — Claude (Anthropic) streaming
OWU: POST /openai/v1/chat/completions
  Authorization: Bearer sk-ant-api03-...
  x-openai-base-url: https://api.anthropic.com/v1
  body: { model:"claude-opus-4-5", messages:[..."Max Mustermann"...], stream:true }

proxy: is_openai=True · actual_path="v1/chat/completions" · is_chat=True
proxy: openai_url = "https://api.anthropic.com/v1" (from header)
proxy: url = "https://api.anthropic.com/v1/chat/completions"
proxy: "Max Mustermann" → PERSON_cc75010d
proxy: Authorization:Bearer → x-api-key + anthropic-version header

→ POST https://api.anthropic.com/v1/chat/completions
  x-api-key: sk-ant-api03-...
  body: { messages:[..."PERSON_cc75010d"...], stream:true }

← LLM: "...PERSON_cc75010d is a developer..." (SSE stream)
proxy: PERSON_cc75010d → Max Mustermann (chunk by chunk)
← user sees: "Max Mustermann is a developer..."
