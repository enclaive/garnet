Garnet — OWU Routing Schema

How connections, urlIdx, FORCE_OPENAI_BASE_URL and x-openai-base-url work together

⚡ Your Understanding vs Reality

Wrong: "the provider URL is in the forced URL"

Correct: FORCE_OPENAI_BASE_URL always points to the proxy — it never changes.
The real provider URL (Anthropic, OpenAI…) travels separately inside the x-openai-base-url header so the proxy knows where to actually forward.

Phase 1 — Admin adds a connection in OWU Settings (done once)

Admin fills the form

URL: https://api.anthropic.com/v1
Key: sk-ant-api03-...

OWU immediately does a GET /models to that URL to fetch the model list.

OWU builds its internal arrays

0 https://api.anthropic.com/v1 sk-ant-api03-***
1 https://api.openai.com/v1 sk-proj-***
2 https://api.groq.com/openai/v1 gsk_***

OPENAI_API_BASE_URLS[idx]
OPENAI_API_KEYS[idx]

Models get stamped with urlIdx

Every model returned from index 0 gets urlIdx = 0 baked in.

Phase 2 — FORCE_OPENAI_BASE_URL: The redirect trick

Without FORCE_OPENAI_BASE_URL

OWU sends directly to the real provider.

url = OPENAI_API_BASE_URLS[idx]
→ https://api.anthropic.com/v1

The message goes straight to Anthropic. No privacy filter.

With FORCE_OPENAI_BASE_URL set

FORCE_OPENAI_BASE_URL=http://privacy-proxy:8080/openai

OWU now sends to the proxy instead:
url = FORCE_OPENAI_BASE_URL
→ http://privacy-proxy:8080/openai

ALL providers go through proxy. One env var intercepts everything.

The key is still OPENAI_API_KEYS[idx] — the real LLM key.
FORCE_OPENAI_BASE_URL only overrides the URL, never the key.

Phase 3 — What OWU sends to the proxy (exact HTTP request)
POST http://privacy-proxy:8080/openai/v1/chat/completions

── Headers ──────────────────────────────────────
Authorization: Bearer sk-ant-api03-XXXXXXXXXXXX ← real LLM key
x-openai-base-url: https://api.anthropic.com/v1 ← real provider URL
x-garnet-entities: PERSON,EMAIL_ADDRESS ← optional PII filter
x-garnet-queryexpand: false
Content-Type: application/json

── Body ─────────────────────────────────────────
{
  "model": "claude-opus-4-5",
  "chat_id": "abc123", ← session key for proxy
  "stream": true,
  "messages": [...] ← contains real PII
}

Authorization header KEY

Contains the real LLM API key. This is what the proxy uses to authenticate with the provider. Comes from OPENAI_API_KEYS[urlIdx].

x-openai-base-url KEY

The real provider URL. Set by OWU from OPENAI_API_BASE_URLS[urlIdx]. This is how the proxy knows WHERE to forward — even though the request arrived at the proxy address.

chat_id in body IMPORTANT

Used by the proxy to build the session_id — the key for storing TOKEN → real_value mappings. Without it, the proxy forgets mappings between messages.

Phase 4 — What happens inside the proxy (first 20 lines of proxy())
1

Catch-all route receives request

path = "openai/v1/chat/completions"
is_openai = path.startswith("openai/") → True
actual_path = "v1/chat/completions"
is_chat = actual_path in ("v1/chat/completions", ...) → True

2

Read the real provider URL from header

openai_url = request.headers.get("x-openai-base-url", OPENAI_API_URL)
→ gets https://api.anthropic.com/v1 from the header OWU sent.
If missing, falls back to the env var default.

3

Self-loop detection IMPORTANT

If x-openai-base-url points back at the proxy itself ("privacy-proxy" or "localhost:8080"), the proxy re-routes by reading the Authorization header key prefix:

sk-ant- → Anthropic  |  AIza / gemini → Gemini  |  gsk- → Groq  |  sk-or- → OpenRouter  |  else → OpenAI

4

Build final destination URL

url = f"{openai_url.rstrip('/')}/{actual_path}"
→ https://api.anthropic.com/v1/v1/chat/completions

This is what the proxy will actually call after pseudonymizing.

5

Strip privacy_proxy flag + extract chat_id

privacy_enabled = body.pop("privacy_proxy", True) — removes it so it doesn't reach the LLM
session_id = body.get("chat_id") or ...
body.pop("chat_id", None) — also removed before forwarding

Summary — The two URLs explained

URL #1 — Where the request goes TO

Set by FORCE_OPENAI_BASE_URL in docker-compose.
Always: http://privacy-proxy:8080/openai

This redirects ALL models through the proxy, regardless of which provider they come from. Never changes at runtime.

URL #2 — Where the proxy forwards TO

Sent in the x-openai-base-url header by OWU.
Comes from OPENAI_API_BASE_URLS[urlIdx] — the real provider URL configured in settings.

Examples:
https://api.anthropic.com/v1
https://api.openai.com/v1
https://api.groq.com/openai/v1

Changes per model/provider.

The key — carried in Authorization

OPENAI_API_KEYS[urlIdx] — the real LLM key.

OWU puts it in the Authorization: Bearer … header.
The proxy extracts it and forwards it to the provider.

For Anthropic: proxy converts Authorization: Bearer sk-ant-... → x-api-key: sk-ant-... (Anthropic's required format).
