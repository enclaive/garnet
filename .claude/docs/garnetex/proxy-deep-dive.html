2 — How OWU Connects to the Proxy

1

Admin adds a connection in OWU Settings

URL: https://api.anthropic.com/v1 + Key: sk-ant-api03-...
OWU does GET /models → gets model list → stamps each model with urlIdx=0

2

FORCE_OPENAI_BASE_URL redirects everything to the proxy

Env var in docker-compose: FORCE_OPENAI_BASE_URL=http://privacy-proxy:8080/openai
OWU code (openai.py:1144): url = os.environ.get("FORCE_OPENAI_BASE_URL") or OPENAI_API_BASE_URLS[idx]
→ ALL models from ALL providers now hit the proxy. The real LLM is never called directly by OWU.

3

OWU sends key + real provider URL in headers

Authorization: Bearer sk-ant-api03-... ← real LLM key (from OPENAI_API_KEYS[urlIdx])
x-openai-base-url: https://api.anthropic.com/v1 ← where proxy should actually forward
chat_id in body ← used by proxy to build session_id

4

Proxy receives at catch-all route

@app.api_route("/{path:path}", methods=["GET","POST","PUT","DELETE"])
path = "openai/v1/chat/completions" → is_openai=True, is_chat=True
Reads x-openai-base-url header → knows real destination

⚠ Self-loop guard: if x-openai-base-url points back at the proxy itself, the proxy re-routes by reading the key prefix in Authorization: sk-ant- → Anthropic, gsk- → Groq, AIza → Gemini, sk-or- → OpenRouter

4 — Session ID: The Identity of a Conversation

# main.py lines 369-373
session_id = (
  body.get("chat_id") # ① OWU passes this — most reliable
  or (messages[0].get("id") # ② fallback: first message id
      if messages else None)
  or (hashlib.md5(first_msg.encode()).hexdigest()[:12] # ③ last resort: hash of first message
      if first_msg else "default")
)
body.pop("chat_id", None) # strip it — LLMs don't know this field
session_id is the KEY used to store and retrieve the token→value mapping. All messages in the same chat share the same session_id → same mapping → tokens are consistent across the whole conversation.

5 — Pass ③: History Depseudonymization

Why restore old assistant messages?

When you send a second message, the full chat history is included in the body. Previous assistant replies contain tokens like PERSON_cc75010d. If the proxy sends those tokens to the LLM unchanged, the LLM answers using tokens and may break context. So the proxy restores them first — the LLM sees the real names in history.

Only old messages

Iterates messages[:-1] (all except the last). Only touches role == "assistant" messages. The last user message gets pseudonymized next.

# main.py lines 403-411
for msg in messages[:-1]: # all except last (the new user message)
  if msg.get("role") == "assistant":
    before = msg["content"]
    msg["content"] = depseudonymize(msg["content"], session_id, store.get_store())
    if msg["content"] != before:
      restored_count += 1

8 — How pseudonymize() Works (pseudonymizer.py)

1

Language detection

langdetect.detect(text) → "en" or "de" (falls back to "en" if unknown).
Determines which spaCy model to load: en_core_web_md or de_core_news_md.

2

Regex pass — fast, high confidence

Before spaCy, run simple regex for:
EMAIL \b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b
PHONE \+\d{1,3}[\s.-]?\d{2,4}...
These are replaced with tokens BEFORE passing text to spaCy, to prevent spaCy from misidentifying them.

3

Strip markdown → spaCy NER

strip_markdown(text) removes **, __, *, backticks to avoid NER confusion.
Returns cleaned text + a position map so we can map back to original positions.
analyzer.analyze() (Presidio) runs on cleaned text → finds: PERSON ORGANIZATION IBAN_CODE LOCATION ID

4

Filter overlaps — regex beats spaCy

Regex results (EMAIL, PHONE) take priority over NER results.
Sorted: regex first, then NER. Overlapping spans → first one wins.
ORGANIZATION: extra filters — must start with uppercase AND score > 0.85.

5

Generate token + replace (right-to-left)

token = f"{entity_type}_{sha256(original)[:8]}"
→ PERSON_cc75010d — deterministic, same value always same token.
Replace from end of string backwards → positions don't shift.
Store: mapping[token] = original

# Token generation — pseudonymizer.py line 54
def generate_token(entity_type, value):
  h = hashlib.sha256(value.encode()).hexdigest()[:8]
  return f"{entity_type}_{h}"

# "Max Mustermann" → sha256 → first 8 hex chars → "PERSON_cc75010d"
# "max@enclaive.io" → sha256 → first 8 hex chars → "EMAIL_ADDRESS_f3a12b99"
# Same value ALWAYS produces same token → consistent across the conversation

9 — Mapping Store (mapping_store.py)

What it stores

Per session, a flat dict of token → original value:


Token (key)Original ValueType
PERSON_cc75010d Max Mustermann PERSON
EMAIL_ADDRESS_f3a12b99 max@enclaive.io EMAIL_ADDRESS
ORGANIZATION_bd3a68a5 Enclaive ORGANIZATION
IBAN_CODE_a1b2c3d4 DE89 3704 0044 0532 0130 00 IBAN_CODE

Two-layer storage

Layer 1: Python dict in memory — fast, lives for process lifetime.

Layer 2: Redis — survives proxy restarts, shared across workers.
Key: garnet:mapping:{session_id}, TTL: 3600s

_RedisAwareStore

Wraps the memory dict. On get(): checks memory first, then Redis. On set(): writes both. flush() force-syncs to Redis.

# mapping_store.py — read path
def get(self, session_id):
  if session_id in self._memory: # ① check memory
    return self._memory[session_id]
  if _redis_client: # ② miss → try Redis
    raw = _redis_client.get(f"garnet:mapping:{session_id}")
    if raw:
      mapping = json.loads(raw)
      self._memory[session_id] = mapping # ③ warm memory cache
      return mapping
  return None # ④ new session
File uploads use a separate namespace: session_id = "file:{file_id}" (via /vault/scan). At chat time, the proxy merges file mappings into the session mapping so file PII is also de-pseudonymized.

10 — Streaming Depseudonymization (stream_with_depseudo)

1

First yield — metadata chunk to OWU

Before any LLM response arrives, sends OWU a special JSON chunk:
{"type":"pseudonymized_prompt","content":"...","file_entity_count":3,"garnet_breakdown":{...}}
OWU uses this to update the privacy badge in the UI.

2

Stream LLM chunks

Opens an httpx streaming connection to the real LLM.
Reads data: {...} SSE lines. Parses choices[0].delta.content from each chunk.

3

Buffer + safe boundary split

Problem: a token like PERSON_cc75010d might arrive split across two chunks:
chunk 1: "hello PERS"   chunk 2: "ON_cc75010d said"

Solution: split_at_safe_boundary(buffer) — holds back any partial token prefix.
Only releases text up to the last safe position. Partial token stays in buffer for next chunk.

4

Replace tokens in safe portion

Sorted longest-token-first to avoid partial replacements.
for token in sorted(mapping.keys(), key=len, reverse=True):
  safe = safe.replace(token, mapping[token])
Yield the de-pseudonymized text as a new SSE chunk.

5

Flush remaining buffer at end

After [DONE] signal, any remaining buffer is flushed and de-pseudonymized.
Then yields data: [DONE] to OWU.

# split_at_safe_boundary — main.py line 72
# Example: buffer = "Max works at PERS"
# → safe = "Max works at " (released to user)
# → remainder = "PERS" (held for next chunk)

for token in TOKEN_NAMES: # PERSON, ORGANIZATION, EMAIL_ADDRESS...
  for length in range(1, len(token)+1):
    prefix = token[:length]
    if buffer.endswith(prefix): # buffer ends with "PERS" → hold it
      safe = buffer[:-len(prefix)]
      return safe, buffer[len(safe):]

11 — Depseudonymizer + Leak Guard (depseudonymizer.py)

Leak guard — what it is

Sometimes the LLM responds with something like:
"PERSON_cc75010d refers to Max Mustermann"

This means the LLM leaked the real name alongside the token. The leak guard detects this pattern and replaces the real value with [REDACTED] before returning to the user.

Trigger patterns

Any of these in the response text:
"refers to"
"stands for"
"is actually"
"real name is"
"which is"
"also known as"
"means"

Normal depseudo flow

After leak guard:
1. Get mapping for session_id
2. Sort tokens longest-first
3. Simple .replace(token, original)

Longest-first prevents a shorter token accidentally matching inside a longer one.

12 — Special Routes

GET /health

Returns {"status":"ok"}. Used by Docker healthcheck and k8s liveness probe.

POST /vault/scan

Called by OWU when a file is uploaded. Body: {text, file_id, privacy_proxy}
Pseudonymizes the full file text. Stores mapping under "file:{file_id}".
Returns entity count + breakdown for the UI badge.

POST /analyze

Runs entity detection only — no pseudonymization, no storage.
Used by the UI to preview which entities would be detected.

GET /openai/api/tags

Proxies to Ollama's /api/tags to list local models.
OWU calls this to populate the local model list.

Image generation (DALL-E)

If model is in IMAGE_MODELS = ["dall-e-3", "dall-e-2", "gpt-image-1"]
→ redirects to /images/generations
→ extracts prompt from last user message
→ sends as simple {model, prompt, n:1, size:"1024x1024"}

Responses API (GPT-5.5+)

Models in RESPONSES_API_MODELS need a different endpoint format.
→ endpoint: /responses instead of /chat/completions
→ body restructured: messages → input, system → instructions
→ max_tokens → max_output_tokens

Ollama (non-streaming)

Ollama path (is_openai=False): always stream=False.
Gets full JSON response, depseudonymizes the message.content field directly.
No streaming → no buffer boundary problem.
