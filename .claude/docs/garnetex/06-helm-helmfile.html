Garnet — Helm Chart vs Helmfile

Two repos, two roles · how they connect · what each file does · concrete image tag example

Big picture — two repos, one deploy

github.com/enclaive/garnet-helm ← THE RECIPE (templates, logic, defaults)
  charts/open-webui/templates/
    workload-manager.yaml ← generates WebUI pod + injects env vars
    privacy-proxy.yaml ← generates proxy pod
    ingress.yaml ← generates Ingress
    websocket-redis.yaml ← generates Redis
    service.yaml ← generates Services
    pvc.yaml ← generates PersistentVolumeClaims
  charts/open-webui/values.yaml ← DEFAULT values (all false/empty)
    ↓ published as OCI artifact
harbor.enclaive.cloud/garnet/open-webui:14.7.1

github.com/enclaive/enclaive-deployment ← YOUR CONFIG (what to deploy, which image)
  118-garnet/helmfile.yaml
    chart: oci://harbor.enclaive.cloud/garnet/open-webui
    version: 14.7.1
    values: ← overrides the chart's defaults
      image.tag: "9bc82f159"
      privacyProxy.enabled: true
      ...

helmfile apply
  → pull chart from Harbor
  → merge helmfile values ON TOP of chart defaults
  → render templates → raw k8s YAML
  → kubectl apply → k8s cluster (garnet.enclaive.cloud)

Simple analogy

garnet-helm = Recipe book

Contains how to build Garnet in k8s.

"If privacyProxy.enabled → create a proxy pod, inject FORCE_* env vars into WebUI"

"Take {{ .Values.image.repository }}:{{ .Values.image.tag }} as the image"

Never changes for a normal deploy. Only changes when the team adds new features to the chart itself.

helmfile.yaml = Your ingredients

Contains what to put in the recipe.

image.tag: "9bc82f159" ← which WebUI version
privacyProxy.tag: "e044d750e" ← which proxy version
memory: 4Gi ← how big
privacyProxy.enabled: true ← which features on

This is what Ahmed edits to deploy a new image or change a setting.

Harbor OCI = Published recipe

The chart is packaged and pushed to Harbor as an OCI artifact.

harbor.enclaive.cloud/garnet/open-webui:14.7.1

version: 14.7.1 in helmfile pins exactly which chart version to use. Upgrading the chart = bump this version.

Concrete example — image tag from helmfile → running pod

Step 1 — helmfile.yaml (your config)
image:
  repository: harbor.enclaive.cloud/garnetdemo/garnet-webui
  tag: "9bc82f159" ← short git SHA of the WebUI image
  pullPolicy: IfNotPresent
Step 2 — workload-manager.yaml (chart template reads your values)
# inside the chart template — not edited by you
{{- with .Values.image }}
  image: {{ .repository }}:{{ include "open-webui.tag" $ }}
  imagePullPolicy: {{ .pullPolicy }}
{{- end }}
Step 3 — rendered k8s manifest (what kubectl actually applies)
# generated — you never write this manually
image: harbor.enclaive.cloud/garnetdemo/garnet-webui:9bc82f159
imagePullPolicy: IfNotPresent
To deploy a new image: change tag: "9bc82f159" → tag: "abc123def" in helmfile.yaml, then run helmfile apply. Nothing else changes.

Concrete example — privacyProxy.enabled injects FORCE_* vars

helmfile.yaml
privacyProxy:
  enabled: true ← this single flag triggers everything below
workload-manager.yaml (chart logic)
{{- if .Values.privacyProxy.enabled }}
- name: "OLLAMA_BASE_URLS"
  value: {{ include "garnet.privacyProxyUrl" . | quote }}
- name: "OPENAI_API_BASE_URL"
  value: {{ printf "%s/openai" (include "garnet.privacyProxyUrl" .) | quote }}
- name: "FORCE_OLLAMA_BASE_URL"
  value: {{ include "garnet.privacyProxyUrl" . | quote }}
- name: "FORCE_OPENAI_BASE_URL"
  value: {{ printf "%s/openai" (include "garnet.privacyProxyUrl" .) | quote }}
{{- end }}
rendered env vars in the WebUI pod
- name: OLLAMA_BASE_URLS
  value: "http://garnet-privacy-proxy:8080"
- name: OPENAI_API_BASE_URL
  value: "http://garnet-privacy-proxy:8080/openai"
- name: FORCE_OLLAMA_BASE_URL
  value: "http://garnet-privacy-proxy:8080"
- name: FORCE_OPENAI_BASE_URL
  value: "http://garnet-privacy-proxy:8080/openai"
You never write these env vars manually in k8s. The chart generates them from one flag. This is also why the helmfile.yaml has no FORCE_* in extraEnvVars — the chart template already handles it.

Chart templates — what each file generates

Template file Generates Controlled by (in helmfile)
workload-manager.yaml WebUI StatefulSet or Deployment + all env vars image.*, extraEnvVars, privacyProxy.enabled, replicaCount
privacy-proxy.yaml Privacy proxy Deployment + Service privacyProxy.* (image, resources, probes)
ingress.yaml Ingress → garnet.enclaive.cloud with TLS ingress.* (host, class, tls, annotations)
websocket-redis.yaml Redis StatefulSet for WebSocket sessions websocket.* (enabled, manager, persistence)
service.yaml ClusterIP Services for WebUI + proxy service.*
pvc.yaml PersistentVolumeClaims (storage) persistence.* (size, storageClass)
garnet-secrets.yaml Secret references (Redis URL, API keys) garnetSecrets.*
garnet-dashboard.yaml Dashboard Deployment + Service garnetDashboard.*

Full deploy flow — step by step

1

You edit helmfile.yaml

Change image.tag, bump a resource limit, toggle a feature. This is the only file you touch.

2

helmfile apply

Helmfile reads chart: oci://harbor.enclaive.cloud/garnet/open-webui + version: 14.7.1
→ pulls the chart OCI artifact from Harbor if not cached locally.

3

Values merge

Chart's values.yaml (defaults) + your helmfile values (overrides) → merged single values map.

4

Template rendering

Helm renders all templates/*.yaml using the merged values → raw k8s manifests (Deployment, Service, Ingress, PVC…)

5

kubectl apply

Rendered manifests applied to namespace garnet on garnet.enclaive.cloud.
k8s pulls the new image from Harbor → rolling update.

Who edits what

You (Ahmed) edit — helmfile.yaml

  • New image tag after a deploy
  • Extra env vars (extraEnvVars)
  • Resource limits (memory/CPU)
  • Feature toggles (privacyProxy, ollama, dashboard)
  • Ingress host / TLS

Team edits — garnet-helm chart

  • New chart feature (new template, new flag)
  • Change how FORCE_* vars are injected
  • Add a new k8s resource type
  • Then publish new chart version to Harbor
  • Then bump version: in helmfile.yaml

Never edit

  • Rendered manifests (auto-generated)
  • Chart defaults values.yaml (override in helmfile instead)
  • Harbor OCI artifact directly
