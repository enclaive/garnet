2 — Open WebUI: how it picks URL and Key (openai.py L1144-1145)

Admin Panel → Connections

Each connection = one array index. Both stored in DB config table.

idxapi_base_urlapi_key
0http://privacy-proxy:8080/openai(empty or WebUI key)
1https://api.anthropic.com/v1sk-ant-...
Model fetch → urlIdx stamped

When WebUI fetches models from connection idx, each model gets urlIdx = idx stamped on it.


At send time (L1144-1145)
url = FORCE_OPENAI_BASE_URL          # env var overrides ALL URLs
   or OPENAI_API_BASE_URLS[urlIdx]   # fallback: DB url by index

key = OPENAI_API_KEYS[urlIdx]        # key ALWAYS from DB by index

⚠ FORCE_OPENAI_BASE_URL overrides the URL for every model, but the key always comes from DB[urlIdx]. The two are independent.

3 — FastAPI Privacy Proxy: routing logic (main.py L338-356)

Step 1 — Detect path type
  • path.startswith("openai/") → OpenAI-compatible route
  • anything else → Ollama route (OLLAMA_URL)
Step 2 — Detect self-loop

If the x-openai-base-url header points back at itself (privacy-proxy or localhost:8080), the proxy knows it must route to a real provider.

Step 3 — Key-prefix routing
Authorization header containsRoutes to
sk-ant-Anthropic
AIza or model has "gemini"Google Gemini
gsk- or model has "groq"Groq
sk-or-OpenRouter
anything elseOPENAI_API_URL (real OpenAI)
Step 4 — Pseudonymize

Last user message scanned by Presidio NER. Real values replaced with tokens:

  • Max Mustermann → PERSON_cc75010d
  • max@co.com → EMAIL_def456
  • +49 89 123 → PHONE_ghi789

Mapping saved in Redis / memory store keyed by session_id.

Step 5 — Forward headers to provider

Proxy forwards only these headers:

  • authorization — or converted to x-api-key for Anthropic
  • content-type
  • openai-organization
  • x-openai-base-url
Step 6 — De-pseudonymize response

Proxy replaces tokens back with real values using the session mapping, then streams result to WebUI.

4 — cVM vs Prod: what is actually different

✅ Prod (k8s / Helm)

  • privacy-proxy pod runs:
    uvicorn privacy_proxy.app.main:app
  • FastAPI app — no auth required to call it
  • Has all Presidio deps installed (presidio_analyzer)
  • Actually pseudonymizes PII
  • Routes by key prefix in Authorization header
  • Helm privacyProxy.enabled=true injects FORCE env vars

❌ cVM (Docker Compose)

  • privacy-proxy container runs:
    uvicorn open_webui.main:app
  • It's a full Open WebUI instance — requires session auth
  • presidio_analyzer not installed → FastAPI proxy can't start
  • No real pseudonymization happening on cVM
  • open-webui sends Anthropic key to privacy-proxy's Open WebUI
  • Open WebUI auth: treats sk-ant-... as a WebUI API key lookup → 404 in users table → 401

5 — Why the 401 happens on cVM (auth.py get_current_user)

Request path: open-webui → privacy-proxy (which is Open WebUI)

open-webui sends
Authorization: Bearer sk-ant-api03-...
→
privacy-proxy (Open WebUI)
get_current_user()

token starts with sk- ?
→ yes →
get_current_user_by_api_key(token)
looks up api_key table
→
NOT FOUND
(Anthropic key ≠ WebUI API key)
→
HTTP 401
"Invalid bearer token"

Root cause: Open WebUI's auth treats any sk-* token as a WebUI API key (stored in its own api_key table). The Anthropic key is not in that table.

On prod this never happens — the privacy proxy is FastAPI with no auth middleware at all. Any request is accepted and processed.

6 — The correct fix for cVM

Option A — Run the real FastAPI proxy (correct)

Install presidio_analyzer in the garnet-webui Docker image and add a command: override to docker-compose.yml for the privacy-proxy service:

privacy-proxy:
  image: harbor.../garnet-webui:...
  command: >
    bash -c "cd /app/backend/privacy_proxy
    && pip install presidio-analyzer presidio-anonymizer
    && python -m spacy download en_core_web_lg
    && uvicorn app.main:app --host 0.0.0.0 --port 8080"

This makes cVM match prod exactly. Ask Seb before doing this.

Option B — WebUI API key passthrough (quick workaround)

1. Generate a WebUI API key in privacy-proxy's Open WebUI for the admin user.
2. Set that key as api_keys[0] in open-webui's DB.
3. Ensure privacy-proxy's Open WebUI has the Anthropic key in its own connections and routes by model name.


⚠ This adds a second key-management layer and no PII pseudonymization. Only use if Option A is blocked.
